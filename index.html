Миграция HSRP → VRRP
без простоя

Автоматическая генерация команд для плавного перехода с HSRP на VRRPv2 / VRRPv3 на двух ядрах сети. Последовательное применение, минимизация разрыва, поддержка аутентификации.

Быстрый старт Исходный код
terminal — hsrp2vrrp
$ python3 migrate_to_vrrp3.py core1.txt core2.txt
# Поочередный перевод HSRP -> VRRPv3 для ядра
# Порядок: сначала standby, затем active для каждого VLAN.
fhrp version vrrp v3
# ========== Vlan2 (group 2) ==========
# --- Standby core (core2.txt) ---
interface Vlan2
no standby 2
vrrp 2 address-family ipv4
address 10.80.68.1 primary
priority 105
timers advertise 5000
preempt delay minimum 180
exit
ip ospf cost 10
... (сгенерировано 22 VLAN)
✓ Сохранено в migrate_vrrp3_sequential.cfg

Возможности

Всё необходимое для безопасной миграции FHRP на двух ядрах сети.

Автопарсинг HSRP

Автоматически находит VLAN и группы HSRP в конфигах обоих ядер. Не нужно вручную выписывать VIP и приоритеты.

Определение ролей

Ядро с большим приоритетом HSRP считается active. При равенстве сравниваются IP-адреса интерфейсов.

Последовательный вывод

Для каждого VLAN команды выводятся в порядке standby → active. Это минимизирует простой хостов.

Аутентификация VRRPv2

Интерактивный выбор: без аутентификации, текстовая или MD5. Единый ключ применяется к обоим ядрам.

VRRPv3 из коробки

Глобальная команда fhrp version vrrp v3 и настройка address-family ipv4.

OSPF cost

Автоматическая установка стоимости OSPF: 1 для active, 10 для standby.

Как это работает

Три шага от конфигов HSRP до готового файла команд VRRP.

1

Экспорт конфигов

Сохраните show running-config обоих ядер в файлы core1.txt и core2.txt.

$ ssh admin@core1 "show run" > core1.txt
$ ssh admin@core2 "show run" > core2.txt
2

Запуск скрипта

Выберите VRRPv2 или VRRPv3. Для VRRPv2 скрипт запросит тип аутентификации и ключ.

$ python3 migrate_to_vrrp2.py core1.txt core2.txt
$ python3 migrate_to_vrrp3.py core1.txt core2.txt
3

Применение

Откройте сгенерированный .cfg и применяйте блоки поочерёдно: сначала standby, затем active.

# Standby core
configure terminal
... вставить блок ...
end
! проверка: show vrrp brief

Схема миграции

Использование

Два скрипта — два сценария. Выбирайте под свою задачу.

VRRPv2

С аутентификацией

migrate_to_vrrp2.py
$ python3 migrate_to_vrrp2.py core1.txt core2.txt
Выберите тип аутентификации для VRRPv2:
1 - Без аутентификации
2 - Текстовая аутентификация (text)
3 - MD5 аутентификация (md5)
Ваш выбор (1/2/3): 3
Введите MD5 ключ: MySecretKey

Формируемые команды:

interface VlanX
 no standby <group>
 vrrp <group> ip <VIP>
 vrrp <group> preempt delay minimum 180
 vrrp <group> priority 110
 vrrp <group> authentication md5 key-string <key>
 ip ospf cost 1

Важно перед применением

  • VRRP использует MAC 0000.5e00.01xx — ARP-таблицы хостов обновятся, возможен кратковременный разрыв.
  • VRRPv3 не поддерживает аутентификацию (RFC 5798). Если она критична — используйте VRRPv2.
  • Проверьте ACL: пакеты VRRP (IP протокол 112, multicast 224.0.0.18) должны проходить.
  • Тестируйте синтаксис на одном VLAN перед массовым применением.
